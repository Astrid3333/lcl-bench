### Two bugs found by tests before anything was trusted
1. **`else if` double-pushed the IF stack.** The first design opened a NEW
   frame per `else if`, so one `end if` closed only the inner frame and the
   outer lingered -> "if not closed before end do". No fixture uses ELSE, so
   only a synthetic snippet caught it. Fix: one frame per if-chain; else/
   else-if re-point `open`/`open_avail`, inner else-if nests an if NODE
   inside the same frame.
2. **Structural jumps and goto targets shared the `("jmp", x)` term.**
   Post-flatten fall-through links store a BLOCK INDEX, while goto terms
   store a LABEL that is resolved later; the resolver then raised "goto to
   undefined label 2" on an ordinary fall-through. Fix: goto keeps
   `("goto", label)` until the resolver rewrites it to `("jmp", idx)`.

### Lessons
- A language subset needs at least one fixture (or synthetic snippet) per
  CONTROL-FLOW feature, not per expression feature: scalar fixtures leave
  the entire else/label machinery untested and it rots silently.
- When a compiler has two kinds of jump (resolved vs unresolved), encode
  them as distinct terms; one tag reused for both turns a resolver into a
  bug generator.
- Re-verify the whole stored-results set against a fresh run after ANY
  codegen change (byte-diff of translated sources + JSON equality): it
  caught nothing this time, which is exactly the evidence worth having.

### Two bugs found by the tests before anything was trusted
1. **Ordered regex alternation**: the for-condition pattern was `(<|<=)`,
   so `i <= 10` matched `<` first and emitted the broken
   `do i = (0) + 1, = 10` into F77. Fixed to `(<=|<)`; the golden
   acceptance test now covers the `<=` path.
2. **Missing trailing comma**: `CONST_SETS = ((("sigma","rho","beta"),"lorenz"))`
   was a 2-tuple, not a tuple-of-tuples → `ValueError: too many values to
   unpack (expected 2)` inside `detect_system` for every unrecognized
   system (i.e. every negative-detection path). Fixed with `,);`.

### Lessons
- Regex alternation is leftmost-first, not longest-match: order the longer
  operator first (`<=` before `<`, `>=` before `>`) and pin it with a
  test that exercises the longer form — a positive test on `<` alone
  cannot see the bug.
- Module-level constants shaped `(tuple, tuple)` vs `((tuple,), ...)` are
  indistinguishable by eye; one test that *iterates* the constant catches
  a missing comma immediately (this one silently disabled an entire
  parser branch for all unknown inputs).
- Writing the branch tests first (`test_translate_c.py` grew while
  `translate_c.py` was still being extended) paid off twice: both bugs
  surfaced before the first green run of the full pipeline, and the 127
  checks now freeze every refusal message and line number.
