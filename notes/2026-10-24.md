## Session: diagnose_attractor layer (next-capacity start)

### Done
- `python/diagnose_attractor.py`: geometric-fingerprint diagnosis. Runs a
  candidate variant (or an external series via `--series`), extracts
  lambda1 (Benettin) + D2 (Grassberger-Procaccia), compares to the registry
  oracle (handles.py + kernels.py, registry protocols) and returns
  `{diagnostico, potencial, confianza, evidence, fingerprint, oracle}`.
- Taxonomy: equivalente | colapso_por_redondeo | artefacto_tipo_sna |
  degradacion_de_orden | diferencia_por_integrador | degradacion_de_precision
  (extension) | inestabilidad_numerica | diferencia_no_explicada.
- Thresholds CALIBRATED on this repo's measurements (not guessed):
  LAM_NOISE=0.02 (measured ulp band on lambda1 was ~±0.015 for
  aizawa/duffing), LAM_REL=0.05 (registry ODE lyap1 rel_tol),
  D2_REL=0.08 (registry henon corr_dim rel_tol), CYCLE_FRAC=0.10.
- Variants synthesized as degraded candidates: reference, float32
  (state cast float32 per step), euler (h=dt), euler_large (h=5*dt).
- Series mode: lambda1=None honestly (needs model function or Wolf
  estimator — not implemented); D2 + cycle detection still work.
- 7/7 expected diagnoses green, reports saved to `results/diagnose/`:
  logistic float32 -> colapso_por_redondeo (lambda1 nan, perturbation
  annihilated); lorenz euler -> degradacion_de_orden (dlambda1=0.136 >
  tol 0.045); lorenz euler_large -> inestabilidad_numerica; both
  references -> equivalente; real henon series -> equivalente (conf 0.75,
  partial); constant series -> colapso_por_redondeo (unique_frac 0.001).

### Bug found & fixed (own code, during verification)
- In candidate_fingerprint the "reference" branch passed the raw RHS as
  the orbit stepper for ODEs (Euler with h=1) -> non-finite orbit ->
  lorenz reference misdiagnosed as inestabilidad_numerica. Same pattern
  in the float32 ODE branch. Fixed: ODE orbits now use the proper
  _rk4_stepper. Lesson: when a code path serves two families (map/ODE),
  the shared loop must receive a family-specific step function — assert
  the identity case (reference) before trusting degraded cases.

### Lessons
- A diagnose layer is only as honest as its thresholds: every constant in
  diagnose_attractor.py cites the measurement or registry tolerance it
  came from. Do not tune thresholds to make a case pass; re-measure.
- Series-only mode must refuse to claim lambda1-class diagnoses
  (SNA vs chaos needs the exponent); report the partial fingerprint with
  lower confidence instead of guessing.

### Taxonomy fix — first classifier was lying (found by fixtures)
- Initial rule: `lambda1=nan` → `colapso_por_redondeo`. WRONG for
  euler_single: measured `unique_frac=1.0` (orbit healthy) — the nan came
  from the 1e-8 Benettin perturbation being annihilated by float32 casting
  (verified: `float32(10.0)+float32(1e-8) == float32(10.0)`), not from an
  orbit collapse.
- Measured to split the branch: logistic float32 uf=0.2155 (genuine
  roundoff collapse) vs lorenz euler_single uf=1.0 vs henon float32 uf=1.0.
  New split: orbit collapsed iff `uf < 0.5 * uf_oracle` (or < CYCLE_FRAC) →
  `colapso_por_redondeo`; healthy orbit + λ1 nan → new label
  `precision_insuficiente` (potencial `migrar_a_double`, conf 0.90), with an
  extra evidence line when the variant is euler (its order shift is masked).

### Lessons
- Never classify on one signal alone: nan/absent invariants must be
  cross-checked against a health signal of the orbit (unique_frac vs
  oracle) before naming the failure mode — the same symptom (λ1 nan) had
  two different physical causes in the same run batch.
- A fixture whose expected label differs from the natural first guess (the
  euler_single case) is exactly what catches a lying classifier: write the
  degraded fixtures BEFORE trusting the taxonomy.

## Session: layer 9 — execute the legacy F77 (translate + run)

### Done
- `python/translate_f77.py`: strict-subset F77 -> Python translator so the
  legacy file is **executed**, not just read. Subset: fixed-form comments/
  continuation/`!`, scalar declarations (`integer`, `real`, `real*4`,
  `real*8`, `double precision`), `parameter` with a numeric literal,
  `+ - * / **` expressions, ONE `do ... end do` (counter excluded from the
  body), `write(*,*)` after `end do`. Everything else raises
  `TranslationError` (arrays, GOTO, multiple loops, C) and the caller falls
  back to the synthetic variant.
- Precision fidelity: literal without `d/D` -> `np.float32(...)`, with ->
  `np.float64(...)`, int//int -> `//`, assignment cast to the declared type
  (emulates legacy REAL). `execution.translated_source` is stored in the
  report and written next to `--out` as `*.translated.py`.
- `parse_legacy_source.analyze()` now runs the F77 first and reports
  `candidate_source: executed_source` + `execution.status =
  executed_source | translation_failed | unsupported_language`. λ1 uses the
  program's own loop count as transient, the source's own `dt` for
  normalisation, and the last 4000 recorded steps for D2.
- 3 F77 fixtures executed: rk4_double -> `equivalente` (λ1 0.895 vs oracle
  0.904, dD2 0.148 vs tol 0.274), euler_single -> `precision_insuficiente`,
  euler_single_huge -> `inestabilidad_numerica`; the C file stays
  `unsupported_language` -> synthetic `precision_insuficiente`. 4/4 fixtures
  + 7/7 diagnose = 11/11 green, suite 24/24 ALL_PASS unchanged.

### Two bugs the fixtures caught before any verdict was trusted
1. **Recorded state selection.** First version recorded every init float that
   the body writes: `['x','y','z','t']` (plus `dt,sigma,rho,beta` in the
   rk4 case). The clock `t` added a monotone coordinate to every pair
   distance and pushed D2 from 1.83 to 1.68/2.27. Fix: record only the first
   `entry.dim` state floats in declaration order -> `['x','y','z']`.
2. **D2 tolerance was under-calibrated.** With the fix, rk4_double still
   failed at exactly 8.1% > D2_REL 8%. Measured the estimator's own noise:
   12 consecutive oracle windows give D2 1.663..1.828 (std 0.058 = 3.3%
   rel), pairwise |dD2|/mean median 3.7%, p90 7.7%, max 9.4% -> **9% of
   independent windows on the SAME trajectory already exceed 8%**, i.e. the
   tolerance manufactured false mismatches. Recalibrated D2_REL 0.08 ->
   0.15 (~4.6 sigma), still 2x below the genuine degradation (euler_single
   36% off). Re-ran all 11 verdicts: none changed.

### Lessons
- Calibrate a comparison tolerance from the estimator's own repeat-measurement
  spread before trusting a borderline pass/fail; a tolerance under 2 sigma of
  that noise turns trajectory realisation into a phantom defect.
- When an executed legacy program disagrees with the oracle, first audit WHAT
  is being compared (state vector vs clock/parameter/scratch), not the
  equations: the wrong recording set corrupted both fingerprints.
